# 变更历史约定

- 实质变更交付或阶段留档时，在 `histories/YYYY-MM/` 维护同一任务的一份 history；不记录逐轮工具流水。
- 新记录文件名用 `YYYYMMDD-<task-slug>.md`；已迁入的发布历史保留原日期与事实，不伪造当前验收。
- 内容包含用户诉求、变更范围、关键取舍、被测版本、验证结果和未验证项，并链接相关计划/专题。
- 原始日志、截图放正常测试产物位置，history 只留关键引用；不存密钥、备份或私人本地路径。
- 长期规则以 `design/` 正文为准；历史决定反转要说明替代关系，不删除重要失败条件。
- 模板：[template.md](histories/template.md)。
