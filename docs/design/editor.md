# 后台编辑器与沉浸模式

## 当前能力与边界

页面状态与命令入口集中在 `src/app/admin/page.tsx`；顶部工具栏和右键菜单分别由 `src/components/admin/markdown-tools.tsx`、`editor-context-menu.tsx` 渲染。Markdown 导入位于 `src/lib/admin-markdown.ts`，选区与格式变换集中在 `src/lib/editor-actions.ts`。

Markdown 导入按钮对外显示「上传 / Upload」，中英文共用既有 `admin.action.uploadMd` 文案键。

- 普通文章编辑含标题、日期、slug、摘要、分类、封面、仅后台可见开关和正文。
- 普通与沉浸模式的正文输入区均关闭浏览器拼写检查，避免英文名称、网址和 Markdown 源码显示拼写波浪线。
- Markdown 工具、源码/预览、目录、清除/保存、可选双向按比例滚动同步。
- 正文编辑维护最多 100 个历史快照，含 Ctrl/Cmd+Z、Shift+Z、Ctrl+Y。
- Markdown 上传是“新建文章”：采用文件日期和元数据，但不沿用 frontmatter/文件名旧 slug，重新生成随机 slug。
- 编辑既有文章保留发布日期与原 slug，除非管理员明确修改；保存刷新 updated_at。
- 沉浸模式是 fixed 全屏工作区，普通/沉浸视图共享正文状态，而非浏览器 Fullscreen API。

以上为源码核对，不能代替本轮浏览器验收。

## 沉浸模式现行约定

保留工具栏、正文、预览、可见性和保存入口；隐藏非必要导航、侧边栏和普通元数据布局，减少干扰。

需要保持的用户路径：

1. 从普通编辑进入沉浸模式，正文与预览保持一致。
2. 编辑文字、插入 Markdown、撤销/重做，在两个模式间切换不丢内容。
3. Escape 和关闭按钮均可退出；退出后普通表单的元数据不被清空。
4. 成功保存后保留正文、预览和编辑模式，转为编辑当前文章；提示条提供“查看文章”与“返回文章库”。失败时保留内容和可重试入口。
5. 仅后台可见状态在两种模式中一致，不能因为隐藏元数据面板而丢失。

旧 2026-06-15 草案称“只有按钮，缺全屏 UI”，已被当前源码替代；不得把已存在的沉浸界面重新列为待开发功能。草案中的退出、同步和发布成功标准仍需真实验收，统一放在主计划。

## 写作右键菜单

2026-11-21 用户参考图方案 accepted，替代此前包含大量插入项及段落子菜单的方案。普通与沉浸模式复用同一菜单，使用后台主题变量适配明暗配色。

- 三行四列图标：剪切/复制/粘贴/删除选中内容，加粗/斜体/行内代码/链接，引用/有序列表/无序列表/任务列表。
- 唯一二级入口“复制 / 粘贴为…”含“复制为纯文本”（Markdown AST 转换，保留代码文字和文本结构）、“粘贴为引用”（剪贴板各行加引用前缀）。普通复制保留 Markdown 原文，普通粘贴读取文本。
- 图标悬停显示名称；空选区禁用剪切、复制、删除及复制为纯文本。菜单自动避让视口边缘，窄屏二级选项在菜单内展开；键盘上下方向键移动焦点，右方向键展开二级菜单，左方向键收起，Escape 关闭菜单并恢复编辑焦点。
- 右键操作复用正文历史与选区恢复；行内格式支持切换，有序列表按选中行编号，列表格式转换替换已有前缀，选区末端恰为下一行开头时保留下一行。
- 命令后通过统一入口恢复选区与焦点：正文更新前记录编辑区横纵滚动位置，更新后先设选区，再以 `focus({ preventScroll: true })` 聚焦并恢复滚动位置。长文格式操作、剪贴板操作和撤销重做保持当前视口；源文与预览同步滚动继续由原有机制处理。
- 剪切先成功写入剪贴板再删除正文；复制/粘贴失败显示提示并保留内容。等待剪贴板期间正文变化或切换编辑模式时，提示重新选择以保护后续编辑。空剪贴板粘贴保留选区内容。
- `Shift + 右键` 打开浏览器原生菜单；`Ctrl/Cmd+B/I/K/E` 与现有撤销重做快捷键继续有效。标题、图片、代码块等沿用顶部工具栏入口。

## 顶部操作按钮与侧边栏折叠

桌面端（`>= 768px`）左侧边栏在展开（`240px`，完整字标＋版本号＋文字导航）与收起（`64px`，居中单 `T` 图标＋纯图标导航及悬停标题提示）之间切换，统一由侧栏顶部品牌区内的同一个 `src/components/admin/sidebar-toggle.tsx` 显式按钮控制（`PanelLeftClose` / `PanelLeftOpen`，维护 `aria-expanded`、`aria-controls="admin-sidebar"` 与中英文标签）：展开态位于版本号右侧，品牌栏高 `60px` 与主内容顶栏底分割线平齐；收起态在品牌区内将单 `T` 品牌标与展开按钮上下紧凑居中排为一组（中间无分割线，仅在组底部保留一条分割线与导航列表分隔）。侧边栏中部空白区域不响应点击切换，避免误触。移动端（`< 768px`）隐藏桌面折叠按钮，沿用汉堡菜单与 `280px` 抽屉，且即使桌面端处于收起态，移动抽屉仍完整显示字标与导航文字。

顶部新建/列表、上传、批量下载和新建密钥共用 32px 高度与 `leading-none`，文字标签复用 `text-trim-caps`，而不是只居中包含字体留白的行盒。标签在小于 640px 时隐藏，保留图标操作。

裁边工具类不设置 display；不支持裁边时仅做轻微位移，避免覆盖响应式 hidden。真实应用验收范围和兼容性限制见 [按钮对齐修复记录](../histories/2026-11/20261113-admin-action-alignment.md)。

## 重构边界

拟定将页面拆为后台布局、内容列表、文章表单、共享编辑工作区，以及预览/历史/同步滚动等 hooks。先固定行为测试再逐块抽取，不同时改 API、持久化语义和视觉布局。

普通与沉浸布局不应分别维护一套保存、工具栏和可见性逻辑。DOM 增强（`.article img` 灯箱、代码复制、目录锚点）有隐式选择器契约，重构时需一并回归。

## 统计口径

后台内容数量来自数据；“字数”当前是标题、摘要、正文拼接后的 JavaScript 字符串长度，不是中文词数或英文单词数。访客/浏览趋势与总访问量是写死的展示数据；相册 Views 是 localStorage 本地计数，不能当作全站访问分析。

趋势图 SVG 渐变通过每个图表实例的 React `useId` 关联，标题只承担本地化展示及无障碍名称。切换语言保持所选周期、曲线路径、尺寸与渐变效果；渐变 ID 独立于标题文字，避免空格导致填充引用失效。
