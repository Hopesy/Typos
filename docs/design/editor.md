# 后台编辑器与沉浸模式

## 当前能力与边界

实现集中在 `src/app/admin/page.tsx`，局部拆出 `src/components/admin/markdown-tools.tsx`、`dashboard-view.tsx`、`tokens-view.tsx`；纯函数位于 `src/lib/admin-markdown.ts`。

- 普通文章编辑含标题、日期、slug、摘要、分类、封面、仅后台可见开关和正文。
- Markdown 工具、源码/预览、目录、清除/保存、可选双向按比例滚动同步。
- 正文编辑维护最多 100 个历史快照，含 Ctrl/Cmd+Z、Shift+Z、Ctrl+Y。
- Markdown 上传是“新建文章”：采用文件日期和元数据，但不沿用 frontmatter/文件名旧 slug，重新生成随机 slug。
- 编辑既有文章保留发布日期与原 slug，除非管理员明确修改；保存刷新 updated_at。
- 沉浸模式是 fixed 全屏工作区，普通/沉浸视图共享正文状态，而非浏览器 Fullscreen API。

以上为源码核对，不能代替本轮浏览器验收。

## 沉浸模式现行约定

保留工具栏、正文、预览、可见性和保存入口；隐藏非必要导航、侧边栏和普通元数据布局，减少干扰。

需要保持的用户路径：

1. 从普通编辑进入沉浸模式，正文与预览保持一致。
2. 编辑文字、插入 Markdown、撤销/重做，在两个模式间切换不丢内容。
3. Escape 和关闭按钮均可退出；退出后普通表单的元数据不被清空。
4. 成功保存后退出编辑/沉浸状态并返回列表；失败时保留编辑内容和可重试入口。
5. 仅后台可见状态在两种模式中一致，不能因为隐藏元数据面板而丢失。

旧 2026-06-15 草案称“只有按钮，缺全屏 UI”，已被当前源码替代；不得把已存在的沉浸界面重新列为待开发功能。草案中的退出、同步和发布成功标准仍需真实验收，统一放在主计划。

## 顶部操作按钮排版

顶部新建/列表、上传、批量下载和新建密钥共用 32px 高度与 `leading-none`，文字标签复用 `text-trim-caps`，而不是只居中包含字体留白的行盒。标签在小于 640px 时隐藏，保留图标操作。

裁边工具类不设置 display；不支持裁边时仅做轻微位移，避免覆盖响应式 hidden。真实应用验收范围和兼容性限制见 [按钮对齐修复记录](../histories/2026-11/20261113-admin-action-alignment.md)。

## 重构边界

拟定将页面拆为后台布局、内容列表、文章表单、共享编辑工作区，以及预览/历史/同步滚动等 hooks。先固定行为测试再逐块抽取，不同时改 API、持久化语义和视觉布局。

普通与沉浸布局不应分别维护一套保存、工具栏和可见性逻辑。DOM 增强（`.article img` 灯箱、代码复制、目录锚点）有隐式选择器契约，重构时需一并回归。

## 统计口径

后台内容数量来自数据；“字数”当前是标题、摘要、正文拼接后的 JavaScript 字符串长度，不是中文词数或英文单词数。访客/浏览趋势与总访问量是写死的展示数据；相册 Views 是 localStorage 本地计数，不能当作全站访问分析。

## 保留的可选需求

自动保存草稿、明确口径的编辑字数统计、仅预览模式、快捷键说明面板均来自旧设计候选项，目前不承诺实施。后续选型、依赖与验收见[主计划](../exec-plans/active/2026-11-13-project-hardening.md)。

浏览器预览和保存缓存见[渲染专题](rendering.md)；可见性与 slug 规则见[数据库专题](database.md)。
