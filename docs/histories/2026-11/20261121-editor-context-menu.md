# 2026-11-21 写作右键菜单精简

## 用户目标

## 变更与理由

- 菜单收敛为基础编辑、行内格式、段落格式共 12 个图标；删除额外插入项及撤销重做菜单项，保留顶部工具栏和原快捷键。组件使用现有后台主题变量，明暗主题共用布局。
- 增加删除选中内容、有序列表；列表格式切换替换已有前缀，选区恰好结束于下一行开头时保留下一行。复制为纯文本复用现有 Markdown 解析依赖，粘贴为引用统一 Windows 换行。
- 剪切在复制成功后才删除选区。复制/粘贴失败有可见反馈；等待剪贴板期间发生后续编辑时保留新内容；空剪贴板保持正文。
- 二级菜单保留可连续移动的悬停区域；窄屏在菜单内部展开。补齐图标标签、空选区禁用状态、方向键移动、Escape 关闭与编辑焦点恢复。
- 清理废弃菜单动作和双语消息键；过程文件集中到 `.Typos-temp/editor-menu/`，Git 与 ESLint 忽略该目录。更新[编辑器专题](../../design/editor.md)与[活动计划](../../exec-plans/active/2026-11-13-project-hardening.md)。

## 追加：长文操作后滚至文末

用户在本地复看发现长文章执行右键功能后跳至底部。先前短文检查未覆盖这一场景。本次保持原文章页，在同一空间的独立草稿页复现和验证。

- **实际复现**：180 段长文文首选中 5 个字符并右键加粗，编辑区 `scrollTop` 从 0 跳到最大值 11852；外层 `window.scrollY` 保持 0。焦点事件显示临时选区为 `[8282, 8282]`，随后虽然恢复到 `[2, 7]`，视口仍停在底部。
- **根因**：React 更新受控 textarea 的值后，临时光标移至文末；`focusPostEditorAt` 先调用默认 `focus()`，浏览器自动将文末光标滚入视野，然后才调用 `setSelectionRange`。
- **修复**：仅调整共用焦点恢复函数，在 DOM 更新前捕获横纵滚动，更新后先设选区，再调用 `focus({ preventScroll: true })`，最后恢复滚动。异步帧执行时确认仍为同一编辑器实例。
- **原复现回归**：同一长文和选区，操作前后编辑区均为 0，恢复焦点时选区已经正确，未产生文末滚动。
- **行为矩阵**：普通/沉浸模式 × 同步滚动开/关 × 文首/第 91 段共 8 组，均覆盖加粗、撤销和重做。文中编辑区保持 `4015.2`；同步开启时预览分别保持 `3732.8`（普通）和 `3725.6`（沉浸）。补验快捷键、顶部工具栏、复制/粘贴（Clipboard API 使用可控夹具），以及防抖预览真正更新后的视口，均保持原位置。
- **本轮质量检查**：目标页面 ESLint、TypeScript、全量 15 文件/49 项测试和生产 Next build 通过。构建期间本地开发服务继续运行；已核对本版本开发产物在 `.next/dev`，构建清理排除该目录。
- **证据**：`.Typos-temp/editor-menu/scroll-before.json`、`scroll-after.json`、`scroll-regression.json`、`scroll-other-actions.json`、`scroll-build.log` 及同目录 `scroll-*.mjs`。

本次修改通过热更新载入本地后台，保留用户原文章页与 3121 开发服务。独立测试页关闭；验证范围为本机 Chromium，Worker、Safari/macOS 继续待验。
